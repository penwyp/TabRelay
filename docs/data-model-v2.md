# v2 数据结构、权限、迁移与保留设计

本设计先于本轮实现提交评审。目标是浮窗统一搜索和可选正文检索，不是网页历史监控或AI知识库。

## 1. 设备私有发布命名空间

沿用 `tabrelay/v1/devices/<deviceId>/` 路径作为传输布局，JSON自身schemaVersion区分结构版本。

```
device.json                      # 设备名、数量、更新时间
current.json                     # 当前SnapshotV1或SnapshotV2
recovery.json                    # 最后非空工作区
history/<readableSnapshotId>.json # v2不可变历史
objects/text/<objectId>.json      # 不可变正文对象（可加密）
```

没有全设备共同写入的聚合文件；搜索聚合只在本地，会话结束可重建。

## 2. 快照与正文引用

SnapshotV2沿用设备、revision、capturedAt、窗口、标签、组和origin字段，新增标签content：

```
content = { status, reason?, ref? }
ref = { ownerDeviceId, objectId, bytes, observedAt, captureUrl }
TextObject = { schemaVersion: 1, extractionVersion: 1, text }
```

status包括available、truncated、disabled、permission-denied、unavailable。bytes为正文UTF-8字节数。captureUrl必须与经过本机隐私规则后的标签URL匹配；正文页面导航前后URL必须相同。正文所有者跨设备恢复/再次发布保持不变，B不能把A的引用错误重写到B目录。缺对象、解密错误或坏引用只影响正文覆盖，不阻止合法标题/URL检索和恢复。

每页20,000字符/60,000字节，单轮100页游标轮转；DOM遍历有节点、深度和200ms时间预算。正文只采样当前已渲染文字，不跟随iframe、不滚动、不读取表单值。限制可能产生截断，需明确显示。

## 3. 加密、不可变性与发布顺序

未加密对象ID为规范TextObject的SHA-256。加密模式采用按设备/用途分离的PBKDF2派生HMAC-SHA256对象ID，避免直接暴露明文词典指纹；正文AES-GCM使用独立AAD绑定所有者和对象ID。快照与正文遵循同一加密口令政策，不能默默用不同口令混存。

先上传/校验正文对象，再持久化pending并发布快照。相同文本复用对象；已存在对象必须解密/验证身份和长度，不能覆盖。失败或中断可能留下孤儿对象，但不能发布假成功正文引用。尝试写对象前持久标记，随后同目录改口令被拒绝；更换目录明确清除运行时旧正文引用并重新采样。旧远端数据不被迁移或重写。

## 4. 可读ID与兼容

v2 ID示例：`20771031-190600Z-r000000000042`。前部UTC日期时间，Z明确时区，revision消除同秒不同发布碰撞；同一个pending重试保持ID不变。历史同时识别旧的12位revision-旧ID文件名，按revision而不是新旧混合字符串排序。

新客户端读取v1和v2，旧v1元数据缺正文时明确标识。所有设备升级后才能互读新v2。此迁移不改写旧历史，不改设备UUID，不删除旧对象。

## 5. 自动增量聚合与清除

本地缓存包含配置指纹、代次、来源快照、正文对象映射和精确来源叶子。IndexedDB分离保存不可变快照与去重正文，已提交缓存容量上限64MiB（唯一密文对象及清单计费），session控制清单另限2MiB；上限2000来源/200000标签作为额外安全边界。所有IndexedDB载荷用AES-GCM加密、随机记录ID，密钥仅放storage.session；会话只存小控制清单，不把正文塞入10MiB session配额。同一worker热缓存避免重复解密，未改变对象不重复写入。事务提交可能短暂同时保留新旧密文；失败写入的孤儿会清理，64MiB并非数据库文件瞬时物理体积保证。清单达到上限会报告部分覆盖，不依赖浏览器配额异常作为正常限流。首次浮窗打开/输入自动加载当前、恢复点及全部保留历史；5分钟刷新元数据，复用未改变的不可变历史与正文，查询本身不遍历远端对象。来源容量/总字节受限，未加载、截断、失败、缺正文和旧数据均为可见覆盖状态。

聚合键考虑URL、标题、正文身份及组/固定状态；source叶子保留device/snapshot/window/tab，选择某一叶子才定位或恢复。所有筛选先于结果限量；精确/包含支持中文，正文命中带安全文本片段，不执行远端HTML。

清空只清本机会话聚合及正文缓存，并持久暂停自动重建。用户明确重建后才重新拉取。配置/隐私/口令变更使旧缓存和预检失效。完整浏览器退出使会话密钥和清单消失；磁盘可能暂留不可解密密文，新会话第一次访问索引时先物理清理旧记录，绝不把旧明文恢复出来。关闭浮窗不影响后台恢复任务和已加载进度。清空、配置/隐私/口令变更与权限撤销会逻辑换代并物理清理索引；迟到写入不得回填旧代。远端保留状态在刷新时核对，不能把历史观察时间称为访问时间。

## 6. 保留与GC的保守边界

历史JSON按数量保留，current/recovery不被清搜索操作删除。正文最多1,000个唯一对象/设备（客户端检查；克隆writer并发不是原子配额），并受单对象长度上限约束。达到上限明确显示metadata-only与正文失败原因。

本版不自动GC远端正文：无服务端事务/锁时，即使完整扫描和复查current仍可能与另一个writer发布引用竞争；宁可留下有界孤儿，不误删保留历史依赖。清本机缓存不释放服务器空间。未来GC需可证明的发布锁/完整引用扫描和失败关闭，不能依赖一次目录扫描。

## 7. 权限与同步时间

默认关闭正文采集。设置页显式站点列表+同意后，才申请可选scripting及精确HTTP/HTTPS origin权限。拒绝通配符、内嵌凭据、无痕窗口、黑名单；排除form/input/textarea/select/contenteditable/hidden/script等，但任意可见正文仍可能包含秘密，必须提示用户自行选择允许站点。

同步间隔枚举5/10/30/60/1440分钟；旧配置默认10。事件立即持久dirty；自动同步按nextDueAt检查，失败也遵循节奏，pending优先重试。手动同步及确认恢复后的合并发布立即执行；浏览器睡眠可延迟，打开浮窗不自动缩短同步间隔。
